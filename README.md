# Вовремя — календарь и чат-бот MAX

Готовый проект мини-приложения: адаптивный календарь, документы, расчёт сроков и сервер напоминаний. Без токена запускается изолированный деморежим. Реальные сообщения появятся после регистрации и подключения вашего бота.

## Быстрый запуск

Требуется Node.js 20.19+ или 22.

```bash
npm ci
cp .env.example .env
npm run dev
```

Откройте **http://localhost:5173**. API работает на порту 3001. Нажмите «Показать примеры» или «Добавить событие». Примеры явно помечены как демонстрационные. Каждый браузер получает отдельный профиль; данные сохраняются в SQLite между перезапусками. Очистка данных браузера теряет доступ к гостевому профилю.

Для проверки импорта загрузите [пример уведомления](public/example-document.txt) через «Добавить документ», выберите **01.12.2026**, подтвердите событие. Для фото и сканированных PDF при первом распознавании нужен интернет для загрузки OCR-моделей.

## Что работает

- Обзор, месячный календарь, переход между месяцами, выбор дня, фильтры, поиск, список выполненных событий.
- Создание, редактирование, завершение и удаление событий. Произвольные сроки можно добавить через «Своё событие».
- Паспорт: выбранное 20-летие / 45-летие по дате рождения, отдельная отметка дня рождения и дедлайн через 90 календарных дней. Прошедшие сроки не скрываются автоматически.
- Флюорография: дата последнего обследования + выбранный интервал врача. Приложение не назначает обследования и не выбирает периодичность за пользователя.
- Имущественные налоги, загранпаспорт и ОСАГО: дата из уведомления или документа. Налоговый срок не рассчитывается универсально: предусмотрены региональные продления и индивидуальные обстоятельства.
- Локальное распознавание JPG/PNG/WebP, текстовых и сканированных PDF, импорт TXT. Извлекаются цифровые даты `ДД.ММ.ГГГГ`, `ДД/ММ/ГГГГ`, `ДД-ММ-ГГГГ` и `ГГГГ-ММ-ДД`; показываются контекст и выбор назначения даты. До 15 МБ, PDF до 5 страниц. Распознанное значение нужно подтвердить; OCR может ошибаться.
- Настройка напоминаний за 90/30/14/7/1 дней и в день срока, локальное время и часовой пояс. Для паспорта дополнительно уведомление в день 20-летия / 45-летия.
- Чат-бот: `/start`, `/help`, `/next`, `/pause`, `/resume`, кнопка открытия календаря. Документы загружаются именно через мини-приложение.
- MAX Bridge, проверка подписи стартовых данных, сессии, защищённый webhook, постоянные очереди событий и отправок, повторные попытки, история доставки.

Это расширяемый каталог основных сценариев, а не полный реестр всех услуг РФ. Прямой интеграции с ЕСИА, ЕГИСЗ или хранилищем документов Госуслуг нет: обычный MAX Bot API такого доступа не предоставляет. Цифровой ID MAX не заменяет API получения произвольных документов.

## Подключение к MAX

1. Зарегистрируйте и верифицируйте профиль на [платформе MAX для партнёров](https://business.max.ru/), создайте бота, пройдите требуемую модерацию. Условия подключения описаны в [документации](https://dev.max.ru/docs).
2. Разместите приложение на сервере с постоянным диском, открытым HTTPS **443** и доверенным TLS-сертификатом. Запуск должен быть непрерывным — напоминания не работают, когда сервер выключен. Для прототипа используется один экземпляр приложения.
3. Настройте `.env` на сервере:

```dotenv
NODE_ENV=production
DEMO_MODE=false
PORT=3001
DATABASE_PATH=./data/vovremya.sqlite
MAX_BOT_TOKEN=your-token
MAX_BOT_USERNAME=your_bot_name
MAX_WEBHOOK_SECRET=replace-with-a-random-secret
APP_URL=https://your-domain.example
MAX_API_URL=https://platform-api2.max.ru
```

Секрет можно сгенерировать командой `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. Не публикуйте `.env` и не добавляйте токен в клиентский код. Если API требует сертификаты Минцифры, установите доверенную цепочку в окружении Node через `NODE_EXTRA_CA_CERTS`; не отключайте проверку TLS.

4. Соберите и запустите:

```bash
npm ci
npm run build
npm start
```

Либо `docker compose up -d --build`. В комплекте есть [Dockerfile](Dockerfile), [compose.yaml](compose.yaml) с постоянным томом и [пример Caddy](docs/Caddyfile.example) для HTTPS. В `.env` для Docker также укажите `PORT=3001`. Сборка Docker здесь не проверялась.

Для запуска на домашнем Windows-компьютере без домена по публичному IP см. [отдельную инструкцию](docs/windows-ip-hosting.md). Она включает бесплатный сертификат Let’s Encrypt и ежедневное продление через порт 443. Приём URL с буквальным IP в MAX нужно проверить в своём аккаунте.

5. В настройках бота укажите публичный HTTPS URL мини-приложения. Адрес `localhost` доступен только на вашем компьютере.
6. Один раз зарегистрируйте webhook:

```bash
npm run bot:subscribe
# При запуске только в Docker:
docker compose exec app node --import tsx server/subscribe.ts
```

Подписка направляется на `https://your-domain.example/api/max/webhook`. События: `bot_started`, `bot_stopped`, `message_created`. После смены домена или секрета выполните подписку снова.

7. Откройте бота, нажмите «Начать», запустите мини-приложение и включите «Получать напоминания». Укажите часовой пояс и сохраните настройки. По умолчанию сообщения скрывают названия документов и медицинских событий; отключите «Скрывать детали», если хотите получать рекомендации прямо в чате.

После первого запуска бота дайте очереди до 15 секунд на обработку; переоткройте приложение для обновления статуса подключения. В производственном режиме гостевой вход и старые демосессии запрещены.

## Как устроены напоминания

Сервер проверяет очередь каждые 15 секунд. Сроки хранятся как календарные даты, сравнение выполняется в часовом поясе пользователя. Сообщение отправляется после выбранного часа, если наступил настроенный порог. При простое восстанавливается только самый свежий пропущенный порог за последние 7 дней. Несколько одинаковых порогов в один день не создают лавину сообщений. Завершение, удаление события, `/pause` и остановка бота прекращают будущие напоминания.

Отправки хранятся в SQLite, ключ содержит событие, дедлайн и порог. Подтверждённые отправки не повторяются после рестарта. При сетевой ошибке — повтор через 5 минут. При тайм-ауте после фактического принятия сообщения MAX повтор возможен: гарантии exactly-once у внешнего API нет. Отправки в один диалог ограничены очередью. Не запускайте несколько экземпляров поверх разных копий базы.

Webhook сохраняется до ответа `200`, затем обрабатывается в фоне; повторы одного события подавляются. Неудачные входящие события повторяются с задержкой до 10 попыток. Для большого числа пользователей нужны отдельный worker, мониторинг, промышленная СУБД и политика хранения данных.

## Данные и границы готовности

Оригиналы файлов, их полный текст, серии и номера документов не отправляются на сервер. После подтверждения сохраняются название файла, выбранная дата, параметры события и заметка; для паспорта это включает дату рождения. В живом режиме также хранится MAX user ID и имя. Непроцессированные сообщения бота временно находятся в очереди. Пользователь может удалить события и историю отправки в настройках.

SQLite не зашифрована приложением. Перед приёмом реальных персональных/медицинских данных настройте защищённый сервер и резервные копии, обработку согласий, сроки удаления, документы оператора и требования к размещению данных. Встроенное удаление событий не удаляет профиль и резервные копии. Демо не следует публиковать для сбора реальных документов.

Правила и источники находятся в `shared/domain.ts` и [docs/sources.md](docs/sources.md). Проверяйте изменения законодательства перед выпуском и поддерживайте каталог. Правила для февраля используют последний существующий день месяца; для индивидуальных правовых пограничных случаев сверьте дату с ведомством.

## Проверки

```bash
npm test                 # даты, подпись MAX, API, изоляция, очереди
npm run build            # TypeScript и production-сборка
npx playwright install chromium
npm run test:e2e         # браузер, мобильная вёрстка, импорт, сохранение
```

В этой среде Chromium установлен в `/tmp/vovremya-browsers`; запуск браузерных тестов здесь: `PLAYWRIGHT_BROWSERS_PATH=/tmp/vovremya-browsers npm run test:e2e`. Отправка в реальный MAX и открытие внутри мобильного клиента требуют вашего бота и внешнего HTTPS-сервера, поэтому не проверены на реальном аккаунте.

## Структура

```text
src/                React-интерфейс, MAX Bridge, OCR и PDF
shared/domain.ts    типы, валидация, шаблоны, даты и расчёт сроков
server/app.ts       HTTP API и webhook
server/auth.ts      проверка MAX initData
server/db.ts        схема SQLite
server/bot.ts       чат-команды, очередь и отправка напоминаний
server/subscribe.ts регистрация webhook
 tests/             модульные, API и браузерные тесты
```
