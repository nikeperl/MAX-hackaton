# Windows-сервер с публичным IP

Развёртывание на Windows по публичному IPv4 без домена. Альтернативный вариант для Windows, Linux и macOS — [Docker с доменом и автоматическим HTTPS](deployment.md).

## Условия

- Docker Desktop в режиме Linux containers и PowerShell.
- Постоянный публичный IPv4, совпадающий с WAN-адресом роутера; локальный адрес или CGNAT не подходят.
- TCP 443 перенаправлен на Windows-компьютер и разрешён в firewall. Локальный IP компьютера закреплён в DHCP роутера.
- Компьютер, Docker Desktop и интернет постоянно работают. После перезагрузки Docker Desktop может потребовать входа пользователя; сон компьютера отключает сервис.
- MAX должен принимать URL с буквальным IP в настройках мини-приложения и webhook. Если платформа отклоняет такой URL, необходим домен.

Сертификат выпускается Let’s Encrypt для IP через TLS-ALPN-проверку. Короткий срок действия требует ежедневной проверки продления. Приватный ключ и ACME-данные хранятся в исключённых из Git папках `deploy/ip/certs/` и `deploy/ip/acme/`.

## Первый запуск

Конфигурация `.env` создаётся на основе `.env.example`; параметры бота описаны в [README](../README.md#окружение-и-рабочий-max). `PUBLIC_IP` содержит адрес без протокола, `APP_URL` — тот же адрес с `https://`.

В PowerShell из корня проекта:

```powershell
docker compose -f compose.yaml -f compose.ip.yaml up -d --build --wait app
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\ip\certificate.ps1 -PublicIp PUBLIC_IPV4
```

В команде `PUBLIC_IPV4` заменяется адресом сервера. Скрипт [certificate.ps1](../deploy/ip/certificate.ps1) выдаёт сертификат, сохраняет его на диск и запускает Caddy. Порт 443 должен быть доступен извне уже в момент выдачи. HTTPS проверяется через внешнюю сеть: домашний роутер может не поддерживать доступ к собственному внешнему IP из Wi-Fi.

После запуска укажите HTTPS-адрес мини-приложения в MAX, зарегистрируйте webhook и выполните диагностику по [deployment.md](deployment.md#сервер-с-доменом), шаги 4–5. Команды `docker compose exec` обращаются к тому же рабочему стеку `max-hackaton`.

## Обновление и остановка

При обновлении используйте те же два Compose-файла:

```powershell
docker compose -f compose.yaml -f compose.ip.yaml up -d --build --wait
docker compose -f compose.yaml -f compose.ip.yaml ps
```

Для временной остановки замените `up ...` на `stop`, для удаления контейнеров и сети — на `down`. Том базы и сертификаты на диске сохраняются; `down -v` удалит базу. При замене всей папки проекта перенесите `.env`, `deploy/ip/certs/` и `deploy/ip/acme/`. Новый сертификат после обычного обновления кода не нужен.

## Продление и автозапуск

В Планировщике Windows создайте ежедневную задачу под учётной записью, запускающей Docker Desktop:

- Программа: `powershell.exe`.
- Аргументы: `-NoProfile -ExecutionPolicy Bypass -File "PROJECT_PATH\deploy\ip\certificate.ps1" -PublicIp PUBLIC_IPV4 -Renew`, где значения заменяются путём к проекту и адресом сервера.
- Режим: для вошедшего пользователя, например ежедневно в 03:00.

Запустите задачу вручную и проверьте код завершения `0x0`. При продлении Caddy временно освобождает порт 443, затем запускается снова. Если сертификат ещё не требует обновления, код `2` от acme.sh считается штатным результатом. При ошибке скрипт пытается вернуть прежний сертификат; контролируйте срок действия и результат задачи.

Для запуска после входа используйте [startup.ps1](../deploy/ip/startup.ps1) от той же учётной записи. При намеренной остановке сервиса отключите связанные задания автозапуска и продления, иначе они могут вновь запустить стек.
