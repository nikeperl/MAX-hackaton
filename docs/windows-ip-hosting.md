# Запуск на Windows по публичному IP без домена

Эта схема использует только входящий TCP-порт 443. Сертификат выдаёт Let’s Encrypt для публичного IPv4-адреса. Он действует 160 часов, поэтому продление нужно запускать автоматически каждый день. На время проверки владения IP HTTPS будет недоступен; само приложение продолжит работать и отправлять напоминания.

MAX требует HTTPS и доверенный сертификат для webhook. Его документация не подтверждает явно, что в поле URL мини-приложения и в подписке webhook допустим адрес без домена. После настройки проверьте оба действия в своём аккаунте MAX. Если MAX отклонит IP, понадобится имя хоста; самодельный сертификат этого не исправит.

## Что нужно

- Windows 10/11 с Docker Desktop в режиме Linux containers и PowerShell.
- Постоянный **публичный IPv4** от провайдера. WAN-адрес роутера должен совпадать с публичным адресом, видимым в интернете. Адреса `10.x.x.x`, `192.168.x.x`, `172.16–31.x.x` и `100.64–127.x.x` за CGNAT не подходят без дополнительного сервера или туннеля.
- Перенаправление входящего TCP 443 с роутера на локальный IP Windows-компьютера и разрешающее правило Windows Firewall для TCP 443. Закрепите локальный IP компьютера в настройках DHCP роутера. Входящий порт 80 не нужен.
- Компьютер, Docker Desktop и интернет должны работать круглосуточно. Отключите сон Windows, включите автозапуск Docker Desktop и оставляйте пользовательский сеанс активным: после перезагрузки Docker Desktop может не стартовать до входа в Windows. Диск с каталогом проекта хранит приватный ключ сертификата; база приложения находится в томе Docker. Не публикуйте `deploy/ip/acme/`, `deploy/ip/certs/` и `.env`.

## Первый запуск

Откройте PowerShell в корне проекта. Скопируйте шаблон настроек и заполните `.env` в редакторе:

```powershell
Copy-Item .env.example .env
notepad .env
```

Укажите `DEMO_MODE=false`, `NODE_ENV=production`, `PORT=3001`, `PUBLIC_IP=ВАШ_ПУБЛИЧНЫЙ_IP`, `APP_URL=https://ВАШ_ПУБЛИЧНЫЙ_IP`, а также `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME` и `MAX_WEBHOOK_SECRET`. Секрет создайте командой:

```powershell
docker run --rm node:22-alpine node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Токен и секрет не отправляйте в чат или GitHub. Затем запустите приложение:

```powershell
docker compose -f compose.yaml -f compose.ip.yaml up -d --build app
```

Получите сертификат. Во время проверки порт 443 на роутере и в Windows уже должен вести на этот компьютер. Подставьте свой IP **без** `https://`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\ip\certificate.ps1 -PublicIp ВАШ_ПУБЛИЧНЫЙ_IP
```

Скрипт сохранит закрытый ключ и цепочку сертификатов в `deploy/ip/certs/`, запустит Caddy и откроет приложение на `https://ВАШ_ПУБЛИЧНЫЙ_IP`. Проверяйте адрес с телефона через мобильную сеть: домашний Wi-Fi может не поддерживать обращение к собственному внешнему IP. Если сертификат не выдаётся, сначала проверьте реальный публичный IP, проброс TCP 443 и что порт не занят другой программой.

## Автоматическое продление

Откройте «Планировщик заданий» Windows → «Создать задачу». Выберите «Выполнять только для вошедшего пользователя» под той же учётной записью, в которой запущен Docker Desktop. Добавьте ежедневный триггер, например 03:00, и действие:

- Программа: `powershell.exe`
- Аргументы: `-NoProfile -ExecutionPolicy Bypass -File "ПОЛНЫЙ_ПУТЬ_К_ПРОЕКТУ\deploy\ip\certificate.ps1" -PublicIp ВАШ_ПУБЛИЧНЫЙ_IP -Renew`

Запустите задачу вручную один раз и убедитесь, что её результат — `0x0`. Скрипт останавливает Caddy, на короткое время занимает порт 443 для TLS-ALPN-проверки, продлевает сертификат при наступлении срока и вновь запускает Caddy. При ошибке он попытается вернуть Caddy с прежним сертификатом. Проверяйте срок сертификата и результат задачи: при шестидневном сертификате длительный сбой быстро отключит HTTPS. Не ставьте задачу от учётной записи, которой недоступен Docker Desktop.

## Подключение MAX

1. Проверьте открытие `https://ВАШ_ПУБЛИЧНЫЙ_IP` с телефона через мобильную сеть без предупреждения о сертификате.
2. В настройках бота укажите эту ссылку как URL мини-приложения. Если MAX её отклоняет, поддержка буквального IP не предусмотрена для этого поля — понадобится имя хоста.
3. Зарегистрируйте webhook:

```powershell
docker compose -f compose.yaml -f compose.ip.yaml exec app node --import tsx server/subscribe.ts
```

4. Проверьте команду `/start`, запуск приложения и тестовое напоминание. Если подписка на `https://ВАШ_ПУБЛИЧНЫЙ_IP/api/max/webhook` отклонена, потребуется имя хоста либо изменение поддержки со стороны MAX.

Не используйте сертификат Let’s Encrypt staging для боевого подключения: он не доверен клиентами. Сертификат в этой инструкции запрашивается сразу у рабочего центра сертификации; избегайте множества повторных попыток при неверном пробросе порта.
