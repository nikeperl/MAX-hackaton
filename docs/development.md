# Разработка

Основной запуск описан в [README](../README.md). Локальный Node.js нужен только для разработки и инструментов.

## Структура

| Каталог или файл                          | Назначение                                                |
| ----------------------------------------- | --------------------------------------------------------- |
| `src/`                                    | React-интерфейс, MAX Bridge, OCR и PDF                    |
| `shared/content.ts`                       | Сферы, единый каталог, рекомендации, тексты и кнопки бота |
| `shared/domain.ts`                        | Валидация, типы, даты и расчёт сроков                     |
| `server/app.ts`, `server/auth.ts`         | HTTP API, webhook и проверка подписи MAX                  |
| `server/db.ts`                            | SQLite, пользователи, события и очереди                   |
| `server/chat.ts`, `server/chat-format.ts` | Формы чата и форматирование ответов                       |
| `server/bot.ts`, `server/max-api.ts`      | Планировщик, повторы и транспорт MAX                      |
| `server/commands.ts`                      | Совместимость с ранее опубликованными командами           |
| `deploy/`                                 | Caddy, IP-сертификаты и публичный корневой сертификат MAX |
| `tests/`                                  | Модульные, API и браузерные проверки                      |

## Локальная разработка

Используйте Node.js 22. Создайте `.env` из `.env.example`, оставьте `DEMO_MODE=true` и выполните:

```sh
npm ci
npm run dev
```

Интерфейс доступен на `http://localhost:5173`, API — на порту 3001. Если рабочий Docker уже использует 3001, задайте в `.env` другой `PORT` и соответствующий `VITE_API_PROXY`, например `PORT=3003` и `VITE_API_PROXY=http://localhost:3003`.

Остановка — Ctrl+C. Production-сборка для ручного запуска: `npm run build`, затем `npm start`. Для постоянного сервера используйте Docker, описанный в [развёртывании](deployment.md).

## Проверки

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

В PowerShell при запрете запуска `.ps1` используйте `npm.cmd` и `npx.cmd`. Браузерные тесты используют изолированную базу `.cache/e2e.sqlite` и порты 3003/5174, не отправляют сообщения в MAX. Для браузеров внутри проекта задайте `PLAYWRIGHT_BROWSERS_PATH=.cache/browsers` при установке и запуске. В Linux при отсутствии системных библиотек используйте `npx playwright install --with-deps chromium`.

Серверные проверки можно выполнить без локального Node.js:

```sh
docker build --target build -t vovremya-check .
docker run --rm vovremya-check npm test
```

Сценарии ручной проверки находятся в [verification.md](verification.md). Скриншоты браузерных тестов `docs/desktop.png` и `docs/mobile.png` используются в презентации.

## Редактирование каталога

Все 46 услуг находятся в одном массиве `templates` в [shared/content.ts](../shared/content.ts). Для новой услуги скопируйте объект, задайте постоянный ID латиницей и заполните те же поля. В `details` всегда присутствуют `conditions`, `source` и `serviceUrl`; отсутствие данных обозначается `null`. Проверенный источник содержит URL и дату `reviewedOn`. Ссылка на портал ведомства сама по себе не подтверждает конкретное правило.

Для подтверждённой даты используйте `calculation: "date"`. `passport` вычисляет возрастной срок, `interval` прибавляет интервал врача. Общие формулировки хранятся над массивом, тексты бота — в `chatCopy`. Сортировка для интерфейса выполняется отдельно; переставлять записи в файле не требуется. Старые числовые ID сохранены только как таблица совместимости с существующими событиями и кнопками.

После правок выполните `npm run api:sync`, `npm test` и `npm run build`. [Отбор исходных случаев](service-catalog.md) объясняет границы каталога; нормативные ссылки и даты проверки редактируются только в записи услуги, без второго справочника в документации.

## Интеграция MAX и данные

Документация платформы: [Bridge](https://dev.max.ru/docs/webapps/bridge), [проверка initData](https://dev.max.ru/docs/webapps/validation), [отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages), [webhook](https://dev.max.ru/docs-api/methods/POST/subscriptions). Требования к регистрации бота публикуются на [платформе MAX](https://dev.max.ru/docs).

Входящие события сохраняются до ответа webhook `200`; результат обработки и изменения записываются транзакционно. Ошибки входящей очереди повторяются с задержкой до 10 попыток. Напоминания проверяются каждые 15 секунд; после простоя выбирается последний подходящий порог за последние 7 дней. Повтор после ошибки отправки — через 5 минут. Завершённые события, остановившие бота пользователи и выключенные напоминания исключаются.

Секреты, SQLite, резервные копии и приватные сертификаты исключены через `.gitignore` и `.dockerignore`. Публичный корневой сертификат MAX нужен для TLS и не является секретом. При изменении безопасности проверяйте историю Git отдельно: проверка текущих файлов не охватывает старые коммиты.

## Презентация и версия сдачи

Источник презентации — [presentation.html](presentation.html); PDF требуется условиями трека. После изменения слайдов установите Chromium, затем выполните:

```sh
node scripts/export-presentation.mjs
```

Экспорт подставляет текущий Git HEAD в PDF, не изменяя HTML. Этот режим предназначен для уже закоммиченной версии исходников. Для сдачи архивом доступны команды:

```sh
node scripts/export-presentation.mjs --snapshot
node scripts/export-presentation.mjs --use-snapshot --private
```

Первая команда создаёт публичный PDF, архив `submission/source.tar.gz` и контрольную сумму `submission/source.sha256`. На первом слайде указывается SHA-256 архива. В архив входят исходники и документация; зависимости, локальные данные, секреты и сам PDF исключены. Требуется утилита `tar`, доступная в современных Windows, macOS и Linux.

Вторая команда создаёт `submission/presentation-private.pdf` с параметрами из локального `.env` для закрытой передачи проверяющим согласно странице 10 задания. Каталог `submission/` исключён из Git и Docker-контекста. Параметр `--previews` сохраняет изображения публичных слайдов в `.cache/presentation/`.

Доступ к API в рабочем режиме даёт подписанная сессия MAX, а в демо — `POST /api/session` с `{}`. Формат `DATA-API.yaml` необходимо сверить со схемой проверяющей платформы. Передаётся одна зафиксированная версия исходников; после дедлайна её не изменяют.
