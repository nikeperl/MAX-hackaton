# Проверка приложения

Запустите демо по [README](../README.md#запуск-через-docker) или рабочий сервер по [инструкции развёртывания](deployment.md). Для проверки используйте синтетические даты и документы.

## Браузер

| Действие                                                                           | Ожидаемый результат                                                          |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Открыть `http://localhost:3002`                                                    | Видна отметка деморежима, отправки в MAX нет                                 |
| Добавить паспорт: дата рождения `20.10.2006`, возраст 20                           | Срок `18.01.2027`, отдельная дата наступления возраста                       |
| Сохранить и перезагрузить страницу                                                 | Событие остаётся в календаре                                                 |
| Открыть рекомендации и завершить событие                                           | Доступны правило, шаги и источник; событие находится среди завершённых       |
| Открыть каталог, выбрать «Жильё и коммунальные услуги», найти водосчётчик          | Список отфильтрован; сферы сгруппированы, названия упорядочены               |
| Импортировать `public/example-document.txt`                                        | Есть дата `01.12.2026`; событие создаётся только после подтверждения         |

| Перезапустить контейнер                                                            | События и настройки сохраняются в томе                                       |

## MAX: чат и мини-приложение

Предварительно выполните диагностику из [deployment.md](deployment.md). Подписка должна включать `message_callback`.

1. Отправьте любое приветствие. Бот предлагает меню и мини-приложение. Нажмите «Добавить событие» → «Личные документы» → «Замена паспорта РФ».
2. Отправьте `20.10.2006`, выберите «20 лет», проверьте срок `18.01.2027` и нажмите «Добавить». Повторное нажатие старой кнопки не создаёт дубликат.
   При переходах по кнопкам бот обновляет одно сообщение. Несколько быстрых нажатий по той же кнопке не должны создавать новые сообщения; проверка работает и после перезапуска контейнера.
3. Откройте «Рекомендации», затем «Мои события». Доступны следующие действия и добавленное событие.
4. В «Настройках» включите напоминания, отправьте в чат время `ЧЧ:ММ` (например, `09:35`), выберите часовой пояс и нажмите «Тестовое уведомление». Бот должен ответить. Это проверяет канал сообщений, а расписание — следующий раздел.
5. Откройте мини-приложение штатной кнопкой MAX. Событие из чата видно под тем же профилем. Завершите его в календаре и проверьте активные события в чате.
6. Нажмите «Добавить следующую дату». Можно запланировать повторное событие. При возврате в уже открытый календарь список обновляется.
7. Повторите путь в мобильном и веб-клиентах MAX. Автотест браузера с мобильным размером не заменяет эту проверку.

## Плановое уведомление

1. Добавьте через кнопки «Своё событие» с сегодняшней датой в выбранном часовом поясе. Включите напоминания и установите ближайшую будущую местную минуту. Проверьте, что сообщение появляется после наступления заданного времени.
2. Закройте мини-приложение и дождитесь отдельного сообщения от бота. Очередь проверяется каждые 15 секунд; возможна задержка сети.
3. При скрытии деталей сообщение содержит общий текст и кнопку «Рекомендации». При отключении приватного режима — конкретные следующие действия.
4. Нажмите «Выполнено». Новые уведомления об этом событии не должны появляться. Звук и push зависят также от настроек MAX и устройства.

## API и автоматические проверки

[OpenAPI](../openapi.json) описывает методы и данные, [DATA-API.yaml](../DATA-API.yaml) — последовательность проверок. Локальная базовая ссылка: `http://localhost:3002/api`.

В демо выполните `POST /session` с `{}` и передавайте полученный `token` в `Authorization: Bearer …`. В рабочем режиме нужны действующие `initData` своего MAX-профиля. Для проверки изоляции создайте две демосессии: событие одной не должно быть доступно другой. Ожидаются `201` при создании, `200` при чтении/изменении, `204` при удалении, `401` без авторизации.

В [fixtures/events.json](../tests/fixtures/events.json) поле `expectedDueDate` служит для проверки результата и не отправляется в API. Команды и зависимости автотестов приведены в [development.md](development.md#проверки). Текущий результат и границы проверки — в [отчёте соответствия](requirements-review.md).
