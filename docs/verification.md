# Пошаговая проверка

Проверка каталога и кнопок: серверные и браузерные тесты, production-сборка. Проверяются мобильный экран 390 px, поиск услуги, сохранение, рекомендации, изоляция пользователей, повторная доставка callback и устаревшие кнопки. Живая подписка MAX должна содержать `message_callback`; это проверяет `bot:check`.

## Локально, без MAX и реальных документов

1. `docker compose -f compose.demo.yaml up -d --build`.
2. Открыть `http://localhost:3002`. Должна быть видна отметка деморежима, отправки в MAX нет.
3. «Добавить событие» → «Замена паспорта РФ» → дата рождения `2006-10-20`, возраст `20` → срок `18 января 2027 г.` → сохранить.
4. Перезагрузить страницу: событие сохраняется. Открыть карточку, прочитать основание и рекомендации, отметить выполненным. Оно перемещается в «Выполненные».
5. «Добавить документ» → `public/example-document.txt` → подтвердить дату `01.12.2026`; автоматически найденные даты не сохраняются без выбора пользователя.
6. «Уведомления» → выбрать часовой пояс и сохранить; после перезагрузки настройки сохраняются. В демо это не приводит к отправке.
7. Проверить мобильный размер 390 px, затем десктоп. Нет горизонтальной прокрутки; доступны календарь, формы и нижняя навигация.
8. `docker compose -f compose.demo.yaml restart`: данные должны остаться. Остановить: `docker compose -f compose.demo.yaml down` (без `-v`). Повторный запуск: команда из шага 1.

## Настоящий MAX: чат без мини-приложения

Нужны рабочий токен, точный ник бота, публичный HTTPS 443, webhook и постоянно работающий сервер. Регистрация: `npm run bot:subscribe`; проверка соединения без сообщений: `npm run bot:check`. Подписка должна включать `message_callback`, иначе нажатия кнопок не поступят серверу.

Основной сценарий с кнопками:

1. Отправить любое приветствие → бот предлагает меню чата и мини-приложение → «Добавить событие» → «Жильё и коммунальные услуги» → выбрать поверку счётчика воды.
2. Отправить дату ДД.ММ.ГГГГ → проверить срок и статус напоминаний → «Добавить». Повторное нажатие старой кнопки не создаёт второе событие.
3. «Рекомендации» → проверить следующие действия → «Главное меню» → «Мои события»: добавленное событие доступно.
4. «Настройки» → включить напоминания, выбрать время и часовой пояс → «Тестовое уведомление». Это проверяет ответ бота, а расписание проверяется отдельно ниже.
5. При скрытии деталей напоминание содержит общие следующие действия и кнопку «Рекомендации». При отключённом скрытии — конкретные рекомендации сразу в сообщении.
6. «Выполнено» → «Добавить следующую дату»: можно запланировать повторную процедуру. Открыть мини-приложение и проверить общий список событий.

Проверка планировщика:

1. Через кнопки добавить событие с сегодняшней датой в выбранном часовом поясе и включить напоминания. Можно выбрать «Своё событие», ввести название и дату.
2. Закрыть мини-приложение. После выбранного часа дождаться отдельного напоминания от бота. Очередь проверяется каждые 15 секунд; при большой нагрузке возможна задержка.
3. Проверить скрытие деталей, кнопку «Рекомендации» и «Выполнено». После завершения новые напоминания об этом событии не приходят.
4. Повторить основной путь в мобильном и веб-клиенте MAX. Звук и push дополнительно зависят от настроек чата и устройства.

## Связь с мини-приложением

Открыть мини-приложение штатной кнопкой MAX. Созданные в чате события видны под тем же MAX-профилем. Завершить событие в календаре и открыть «Мои события» в чате — его больше нет среди активных. После действия в чате вернуть фокус в открытое мини-приложение: список и статус бота обновляются. Несохранённые настройки формы не должны теряться.

## API

`openapi.json` описывает методы, `DATA-API.yaml` — декларативную последовательность проверок. В демо создать сессию `POST /api/session` с `{}`, взять `token` и передавать `Authorization: Bearer …`. В production использовать только проверенные MAX initData; универсального пароля нет. В `tests/fixtures/events.json` служебное поле `expectedDueDate` предназначено для сравнения результата, а не для отправки в API.

Автоматически: `npm test`, `npm run build`, `npm run test:e2e`. Браузерные тесты используют отдельную базу `.cache/e2e.sqlite`, порты 3003/5174 и не используют рабочий токен. Для установленных в проекте браузеров в PowerShell: `$env:PLAYWRIGHT_BROWSERS_PATH='.cache/browsers'`.
