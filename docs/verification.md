# Пошаговая проверка

## Локально, без MAX и реальных документов

1. `docker compose -f compose.demo.yaml up -d --build`.
2. Открыть `http://localhost:3002`. Должна быть видна отметка деморежима, отправки в MAX нет.
3. «Добавить событие» → «Замена паспорта РФ» → дата рождения `2006-10-20`, возраст `20` → срок `18 января 2027 г.` → сохранить.
4. Перезагрузить страницу: событие сохраняется. Открыть карточку, прочитать основание и рекомендации, отметить выполненным. Оно перемещается в «Выполненные».
5. «Добавить документ» → `public/example-document.txt` → подтвердить дату `01.12.2026`; автоматически найденные даты не сохраняются без выбора пользователя.
6. «Уведомления» → выбрать часовой пояс и сохранить; после перезагрузки настройки сохраняются. В демо это не приводит к отправке.
7. Проверить мобильный размер 390 px, затем десктоп. Нет горизонтальной прокрутки; доступны календарь, формы и нижняя навигация.
8. `docker compose -f compose.demo.yaml restart`: данные должны остаться. Остановить: `docker compose -f compose.demo.yaml down` (без `-v`). Повторный запуск: команда из шага 1.

## Настоящий MAX: чат без мини-приложения

Нужны рабочий токен, точный ник бота, публичный HTTPS 443, webhook и постоянно работающий сервер. Регистрация: `npm run bot:subscribe`; проверка соединения без сообщений: `npm run bot:check`. Меню MAX содержит команды и подсказки.

1. Открыть личный диалог бота → `/start`: бот перечисляет команды.
2. `/passport 20.10.2006 20`: появится срок 18.01.2027 и постоянный код события.
3. `/show код`: видны основание расчёта, шаги и ссылка на источник.
4. `/next`: событие присутствует. `/time 9 Asia/Novosibirsk`, затем `/resume`: бот подтверждает час, пояс и включение.
5. `/test`: сообщение приходит от бота. Это проверка ответа на команду, а не планировщика.
6. Для отдельной проверки расписания установить `/time 0 Asia/Novosibirsk`, затем `/add ДД.ММ.ГГГГ Тест уведомления`, подставив сегодняшнюю дату в этом поясе. Закрыть мини-приложение. В течение примерно 15 секунд при свободной очереди должно прийти отдельное напоминание от бота; с большой очередью задержка увеличится.
7. При `/privacy on` название скрыто, но команда `/show код` раскрывает детали по запросу. При `/privacy off` последующие напоминания содержат название и рекомендации.
8. `/done код`: событие завершено, дальнейших напоминаний о нём нет. `/pause`: отправки остальных событий выключены.
9. `/add 31.02.2026 Ошибка`: понятная ошибка без создания события. Команды в групповом чате игнорируются.
10. Повторить основной путь в мобильном и веб-клиенте MAX, зафиксировать результат и время. Звук/push дополнительно зависит от настроек чата и устройства.

## Связь с мини-приложением

Из сообщения бота открыть календарь. Созданные в чате события видны под тем же MAX-профилем. Завершить событие в календаре и вызвать `/next` в чате — его больше нет среди активных. После команды из чата вернуть фокус в открытое мини-приложение: список и статус бота обновляются. Несохранённые настройки формы не должны теряться.

## API

`openapi.json` описывает методы, `DATA-API.yaml` — декларативную последовательность проверок. В демо создать сессию `POST /api/session` с `{}`, взять `token` и передавать `Authorization: Bearer …`. В production использовать только проверенные MAX initData; универсального пароля нет. В `tests/fixtures/events.json` служебное поле `expectedDueDate` предназначено для сравнения результата, а не для отправки в API.

Автоматически: `npm test`, `npm run build`, `npm run test:e2e`. Браузерные тесты используют отдельную базу `.cache/e2e.sqlite`, порты 3003/5174 и не используют рабочий токен. Для установленных в проекте браузеров в PowerShell: `$env:PLAYWRIGHT_BROWSERS_PATH='.cache/browsers'`.
